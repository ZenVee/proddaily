# PROD DAILY | Complete Backend Implementation

## Project Overview

You are working on **Prod Daily**, an existing web application featuring daily Wordle puzzles, custom crosswords, user profiles, and an administrative dashboard.

The frontend has already been designed and developed.

Your task is to implement the complete backend using **Supabase Cloud**, integrating it with the existing frontend.

### Technology Stack

- Frontend: Existing React / TypeScript application
- Database: Supabase PostgreSQL
- Authentication: Supabase Auth with Discord OAuth
- File Storage: Supabase Storage
- Backend Logic: Supabase Edge Functions, PostgreSQL functions, and secure database operations where appropriate
- Security: Row Level Security (RLS) and server-side permission validation

Do not unnecessarily rebuild or redesign the existing frontend.

Preserve existing components, layouts, styling, and interactions while replacing mock data and simulated backend functionality with real Supabase integrations.

# 2. Database Architecture and Migrations

Create a complete PostgreSQL schema for the application.

## Migration Naming Convention

Every database migration must have a clearly identifiable filename.

Use the following convention:

`migration_001_initial_schema.sql`

`migration_002_auth_profiles.sql`

`migration_003_roles_permissions.sql`

Continue using sequential numbering.

Never create database migrations without the `migration_` prefix.

## Master SQL File

Maintain a file named:

`master_schema.sql`

This file must represent the complete database schema required to set up Prod Daily on a fresh Supabase project.

Whenever a migration is created or modified:

1. Update the master SQL file.
2. Keep all tables, indexes, functions, triggers, policies, and required seed data synchronized.
3. Make the master file safe to execute on a fresh Supabase installation.
4. Avoid duplicate definitions and conflicting policies.
5. Preserve migration history.

The master schema must not include production user data or secrets.

Do not overwrite an existing production database with the master file.

If the project already has migrations, inspect them and continue the existing sequence without rewriting applied migrations.

## Database Requirements

Use:
- UUID primary keys where appropriate.
- Foreign keys.
- Appropriate unique constraints.
- Timestamps with time zones.
- Indexes for frequently queried columns.
- Database-level validation.
- Row Level Security.
- Secure PostgreSQL functions where appropriate.

Use `auth.users` as the source of authenticated identities.

Do not create a separate password authentication system.

# 3. Discord Authentication

Implement authentication using Supabase Auth with Discord as the OAuth provider.

## Login Flow

When a visitor clicks Sign in with Discord:

1. Start the Supabase Discord OAuth flow.
2. Redirect to Discord authorization.
3. Process the Supabase authentication callback.
4. Establish the authenticated session.
5. Retrieve the authenticated user's Supabase ID and Discord identity.
6. Check for an existing Prod Daily profile.
7. If profile setup is incomplete, redirect to `/profile/setup`.
8. Otherwise, return the user to the application.

Use Supabase's authenticated identity information rather than trusting Discord IDs submitted by the frontend.

## First-Time Login

When a user authenticates for the first time:

- Create a profile record automatically.
- Assign the User role by default.
- Store the Discord user ID.
- Store the Discord username.
- Store the Discord avatar URL.
- Record the account creation timestamp.
- Mark profile setup as incomplete.

The initial profile creation must be idempotent to prevent duplicate records.

Users with incomplete profiles should be directed to profile setup before accessing account-specific functionality.

## Returning Users

For returning users:

- Restore their authenticated session.
- Load their profile.
- Load their role and applicable permissions.
- Restore their personal preferences.
- Continue to the requested page when authorized.

Implement sign-out and session expiration handling.
